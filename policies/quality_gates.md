# Quality Gates Policy
**PMBOK Reference:** 8.2 Manage Quality | Knowledge Area: Quality Management

---

## Purpose

Quality gates are mandatory checkpoints at the end of each project phase or major milestone. No project may proceed to the next phase until all quality gate criteria are met and formally signed off.

---

## Quality Gate Framework

```
INITIATION → [Gate 0: Go/No-Go] → PLANNING → [Gate 1: Planning Complete] 
    → EXECUTION → [Gate 2: Mid-Project Review] → TESTING/VALIDATION 
    → [Gate 3: Delivery Readiness] → GO-LIVE → [Gate 4: Project Closure]
```

---

## Gate 0: Project Authorization (End of Initiation)

**Purpose:** Confirm the project is worth starting.

| Criterion | Required | Evidence | Pass/Fail |
|---|---|---|---|
| Business case approved | Yes | Signed Business Case | |
| Project Charter signed | Yes | Signed Charter | |
| Sponsor identified and committed | Yes | Sponsor signature | |
| Initial stakeholders identified | Yes | Stakeholder Register v1.0 | |
| High-level budget allocated | Yes | Budget approval | |
| Strategic alignment confirmed | Yes | Executive sign-off | |

**Gate Decision Authority:** Sponsor + Executive Leadership

**Outcome:** GO (proceed to planning) / NO-GO (revise or cancel) / CONDITIONAL GO (proceed with conditions)

## Gate 2: Mid-Project Health Check

**Purpose:** Assess project health at ~50% completion and confirm viability.

| Criterion | Required | Pass Threshold | Pass/Fail |
|---|---|---|---|
| Schedule Performance Index (SPI) | Yes | ≥ 0.90 | |
| Cost Performance Index (CPI) | Yes | ≥ 0.90 | |
| % deliverables on track | Yes | ≥ 80% | |
| Critical risks under control | Yes | No unmitigated Critical risks | |
| Stakeholder satisfaction | Yes | ≥ 3.5/5.0 | |
| No unresolved critical issues | Yes | Issue log < 2 critical open | |
| Change requests within tolerance | Yes | Scope growth < 10% | |

**Gate Decision Authority:** Steering Committee

**Outcome:** Continue / Recovery Plan Required / Re-baseline / Cancel

---

## Gate 3: Delivery Readiness (Pre-Go-Live / Pre-Delivery)

**Purpose:** Confirm deliverables are ready for acceptance.

| Criterion | Required | Pass Threshold | Pass/Fail |
|---|---|---|---|
| All deliverables complete | Yes | 100% | |
| Acceptance criteria verified | Yes | All criteria met | |
| UAT / testing passed | Yes | 0 Critical defects, <3 High | |
| Documentation complete | Yes | All docs reviewed | |
| Training complete | Yes | All users trained | |
| Rollback / contingency plan ready | Yes | Plan documented | |
| Stakeholder sign-off on readiness | Yes | Customer approval | |
| Support/operations team ready | Yes | Handover acknowledged | |

**Gate Decision Authority:** Sponsor + Customer

---

## Gate Failure Procedure

1. PM documents which criteria failed and why
2. PM creates a remediation plan with owner and target date
3. Remediation is implemented (max 2 weeks for Gate 0–2; max 1 week for Gate 3–4)
4. Gate is re-assessed
5. If gate fails a second time → escalate to Steering Committee

**A failed gate does NOT mean the project is cancelled** — it means corrective action is required before proceeding.
